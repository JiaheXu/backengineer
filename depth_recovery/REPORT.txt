NETWORK STRUCTURE OBSERVED IN THE GRAPHS
All four have two stereo inputs, left/right, shaped [batch,3,height,width], and
three outputs: disparity, disparity_right and confidence. These are disparity
networks; camera calibration and SDK processing turn disparity into metric depth.
Original internal node and tensor names are obfuscated, but the topology,
operators, kernel shapes, connections and weight tensors remain available.

Common structure:
  Stereo inputs
    -> reshape/transpose packing of 2x2 spatial neighborhoods into 12 channels
    -> shared left/right convolutional feature extraction
    -> stereo cost volume
    -> cost processing and disparity estimation
    -> local offset cost volumes and learned refinement
    -> left/right disparity and confidence outputs

neural_depth_5.3:
  FLOAT inputs; FLOAT weights; ONNX opset 16.
  77 Conv nodes (70 2D, 7 3D), 3 3D ConvTranspose nodes.
  Shared first feature kernel [64,12,7,7], stride 2; a separate
  [16,12,3,3] convolutional branch is also present.
  sl::build_gwc_volume(max_disp=24,num_groups=32).
  Three sl::build_offset_volume(max_offset_disp=3,num_groups=1) nodes.
  Cost processing includes 3D convolution and spatial upsampling.
  Outputs include Softmax/ReduceSum disparity computation and Sigmoid confidence.

neural_depth_light_5.3:
  FLOAT inputs; FLOAT weights; ONNX opset 16.
  60 Conv nodes, all 2D; no ConvTranspose.
  Shared first feature kernel [64,12,7,7], stride 2.
  sl::build_gwc_volume(max_disp=24,num_groups=1).
  Two sl::build_offset_volume(max_offset_disp=3,num_groups=1) nodes.
  Includes feature normalization, 2D processing and upsampling/refinement.

neural_depth_5.4 and neural_depth_5.6:
  79 Conv nodes (72 2D, 7 3D), 3 3D ConvTranspose nodes.
  CensusXnorCostVolume(census_bits=512,groups=32,max_disp=24) replaces
  the explicit build_gwc_volume seen in the 5.3 graph.
  Each includes 66 QuantizeLinear and 66 DequantizeLinear nodes, and three
  sl::build_offset_volume(max_offset_disp=3,num_groups=1) nodes.
  5.4 uses FLOAT inputs and predominantly FLOAT initializer tensors, opset 16.
  5.6 uses FLOAT16 inputs and predominantly FLOAT16 initializer tensors, opset 19.
  Both preserve quantization scales and INT8 zero-point tensors in NPZ.
  Quantized convolution weights can be produced through graph Q/DQ operations;
  the initializer archive preserves what was actually shipped.

No particular published architecture (RAFT, CREStereo, etc.) is established by
this evidence. The custom-depth sample downloads alternative networks; it does
not demonstrate which network the built-in depth modes use.
The exact runtime mapping of every artifact to NEURAL/NEURAL_PLUS and hardware
fallback selections was not traced. Filenames alone do not establish that map.

Static GNU objdump analysis located a CPU decoder at library offset 0x191ab0.
The call at 0x18e580 supplies input bytes, length, an output std::vector and
optional metadata. Its failure path reports v2 model decrypt/inflate failure.
extract_model.cpp loads this installed library and calls that same decoder with
null optional metadata. All four returned rc=0 and nonempty ONNX payloads.
This helper depends on the exact installed binary and C++ ABI; do not use its
hardcoded offset against another SDK build. It is not a portable standalone
reimplementation of the encryption scheme.
Focused disassembly evidence is retained in evidence/*.asm.
REA MCP tools were unavailable, and npm acquisition failed with EAI_AGAIN.
The evidence here comes from ordinary shell analysis and actual decoder runs,
not REA-generated evidence records.

VALIDATION AND LIMITS
5.3 and light 5.3 pass onnx.checker.check_model on the original exported files.
5.4 and 5.6 parse successfully, but the checker rejects CensusXnorCostVolume
because it is a proprietary op placed in the default ONNX domain. Assigning it
to sl in a temporary in-memory copy lets the remaining structural checks pass;
the delivered ONNX files are unmodified. Custom-op semantics are not validated
by this check, including for the models that pass directly.

All NPZ tensors round-trip byte for byte against every ONNX initializer.
This recovers the shipped inference graphs and tensors, not training source,
original pre-export parameter names, gradients or optimizer checkpoints.
Standalone inference needs implementations/plugins for build_gwc_volume,
build_offset_volume and, for 5.4/5.6, CensusXnorCostVolume. PyTorch translations
of those operators and all four graphs are now implemented and tested; see
PYTORCH_USAGE.txt and evidence/custom_ops_notes.txt for validation and limits.
Exact SDK preprocessing, calibration, runtime
artifact selection and output postprocessing were not fully traced. No GPU
inference or numerical equivalence comparison against SDK depth was performed.
